# dnsdoc ideas — post v0.4.0 brainstorm

Requested brainstorm, not a commitment list. Nothing here is scheduled;
pick what's worth a real spec when you're ready.

## More functions

1. **DoH/DoT query support** — query resolvers over DNS-over-HTTPS/TLS,
   not just plain UDP/TCP:53. Useful for testing modern resolver
   reachability and for checking whether a network is blocking classic
   port 53 while DoH still gets through.
2. **NSID / anycast node identification** — the `time` profile's two
   anycast VIP pairs (ANS-ANYCAST, CACHE-ANYCAST) answer from whichever
   physical node is closest. Send an EDNS NSID request (RFC 5001) and
   show which node actually answered — right now Propagation can't tell
   you that, only that *an* answer came back.
3. **Resolver health scoreboard** — a view that ranks resolvers within
   the active profile by uptime %, latency p50/p95, and consensus
   agreement over time. Most useful for `time` and `custom`, where
   you're actively comparing infra you operate rather than trusting
   public resolvers to just work.
4. **Headless/batch mode** — `dnsdoc --batch domain1.com domain2.com`
   runs every check non-interactively and dumps the same markdown/JSON
   `report.rs` already renders, one per domain. Makes dnsdoc usable from
   cron or CI instead of only interactively.
5. **`dnsdoc doctor`** — a startup self-check: parse `config.toml`, flag
   unknown fields, then ping-test every configured resolver (across all
   profiles) and report which are unreachable *before* you rely on them
   mid-diagnosis.
6. **Profile export from the TUI** — a key that dumps the active
   profile's resolvers as a ready-to-paste `[[profile]]` TOML block, so
   a `custom` profile built up interactively can be promoted into
   `config.toml` (or shared with a teammate) without hand-typing IPs.
7. **Per-profile query timeout override** — private infra resolvers
   (like `time`'s) may need a different timeout than public ones. Right
   now timeout is presumably global; a `timeout_ms` field per `[[profile]]`
   would let a slow internal cache not get flagged as dead by a timeout
   tuned for 8.8.8.8.
8. **Delete/edit from the custom-resolver popup** — today `a` only adds.
   A `d`-while-picker-on-custom-row to drop a bad entry avoids hand-editing
   `custom_resolvers.json`.
9. **Report diffing** — compare the current run's JSON export against a
   previously saved one, and highlight what changed (new failing check,
   resolver that stopped answering, TTL drift) instead of re-reading two
   full reports side by side.
10. **Query history log** — like Monitor's persisted change log, but for
    every ad-hoc reverse lookup and custom-resolver test query, so you
    can look back at what you tested against a given server yesterday.

## Appearance / UX

1. **Themeable ttyd wrapper page** — dnsdoc is served raw through ttyd
   at `10443`. A minimal HTML shell around the terminal (title, favicon,
   one-line "what is this") would make the link presentable to send to
   someone who isn't already read into the project.
2. **Color-coded profile badges** — now that there are 5 profiles
   (all/global/privacy/time/custom), give each a distinct accent color
   in the header and picker so the active one is recognizable at a
   glance, not just by reading its name.
3. **Mouse support** — ratatui/crossterm both support mouse events;
   clicking a tab or a profile-picker row would suit the ttyd/browser
   audience better than assuming everyone knows the keybinds.
4. **Persist last domain + profile** — remember the last session's state
   across restarts, so the always-on ttyd demo doesn't reset to an empty
   input box every time the container restarts.
5. **Toast-style status messages** — the status line currently gets
   overwritten immediately; a short-lived toast (e.g. "saved resolver
   lab-dns" visible for ~2s then reverting) would avoid the current
   flash-and-forget feel.
6. **Latency heatmap on Monitor's sparkline** — color-gradient the
   existing per-resolver sparkline by latency band instead of a single
   color, so a slow resolver is visible without reading the numbers.
7. **First-run welcome screen** — replace the empty input box on cold
   start with a one-screen keybind cheat sheet, useful for anyone
   landing on the ttyd link cold.
8. **Command palette** — a `:`-triggered command line (`:profile time`,
   `:domain example.com`) for people who'd rather type than navigate
   pickers, vim-style.
9. **HTML export** — `e` currently writes markdown + JSON; a rendered,
   syntax-highlighted HTML report would be shareable outside a terminal.
10. **Density toggle** — a compact-row mode for the propagation/audit
    tables so more resolvers fit on screen without scrolling, useful
    once a profile like `time` (14 resolvers) is active.
